# Реестр vs техническое хранилище

Google Sheets — **реестр для человека**, не база данных бота.  
В таблице только то, что нужно глазами проверить статус заявки.  
Все служебные id и связи бот хранит **отдельно** (БД / локальный store).

---

## Лист «Реестр» (для людей)

Минимум колонок, понятных без расшифровки:

| Колонка | Пример | Смысл |
|---------|--------|--------|
| Дата | 21.10.2026 14:05 | когда приняли в работу |
| Контрагент / накладная | ИП БАТУРИН, №2744 | текст подписи из Telegram |
| Файлов | 3 | сколько вложений ушло |
| Статус | Письмо отправлено / Получено / Внесено / Исключение / Ошибка | текущий этап |
| № обращения | 059137937 | из письма DocsInBox (пусто до 📥) |
| Документ DocsInBox | СП0000000081984 | после внесения (пусто до ✅) |
| Ссылка | https://dxbx.ru/... | после внесения |
| Ошибка | Gmail timeout | только если статус Ошибка, иначе пусто |

### Не писать в этот лист

- `chat_id`, `message_id`, `media_group_id`, `file_id`
- update_id, Gmail message id, thread id
- внутренние UUID бота
- сырые JSON, токены, пути S3

Эмодзи в чате дублируют **Статус**; детали ошибок — в колонке «Ошибка», без технических стектрейсов (короткая фраза).

---

## Лист «Исключения» (для людей)

Одна колонка (или две: название + комментарий) — список контрагентов.  
Редактируется вручную, бот только читает.

---

## Техническое хранилище (только для бота)

Отдельная БД (рекомендуется SQLite на старте / Postgres позже) или скрытый машинный слой — **не** основной реестр Sheets.

На одну заявку хранить, например:

| Поле | Зачем |
|------|--------|
| `internal_id` | первичный ключ бота |
| `sheet_row` | номер строки в реестре (чтобы обновлять статус) |
| `chat_id` + `message_id` | куда ставить реакции |
| `media_group_id` | отладка альбома |
| `file_ids` / пути вложений | повтор / аудит |
| `outgoing_subject` | полная тема исходящего |
| `gmail_message_id` / `thread_id` | надёжный матчинг ответов |
| `appeal_number` | № обращения (дубль для поиска) |
| `status` | дубль статуса для логики |
| timestamps этапов | служебные метки времени |

Связка: бот меняет статус в БД → зеркалит **человеческие** поля в Sheets → меняет эмодзи по `message_id` из БД.

---

## Поток данных

```
Telegram → бот → БД (id, message_id, …)
                ↘ Sheets (дата, подпись, статус, № обращения, ссылка, ошибка)
                ↘ реакция в чате
Gmail reply → бот → поиск в БД → обновление БД + Sheets + реакция
```

Sheets всегда можно пересобрать/починить из БД; наоборот — нет (в таблице нет id сообщений).
